# 4net lobby server

[中文](README.md)

The server behind the "lobby server" connection mode. It does three things only:

1. **Room list**: a host registers every 2 seconds (name / map / full or not / LAN address); a room with no heartbeat for 10 seconds is removed. Clients fetch the list.
2. **Address introductions**: when a client joins, the server tells each side the other's public address (the NAT address the server sees) and LAN address, and the two punch a direct connection themselves.
3. **Relay (off by default)**: you can relay only the spectator stream (`--relay-watch`), or turn on match relay as well with `--relay`. With match relay on, after 3 failed direct attempts the client asks for relay and both sides' state packets go through the server (120 packets/s per session per direction; the game sends 30/s). With relay off the server answers "no relay", the client panel suggests port forwarding or Tailscale on the host, and keeps retrying direct.
   Players choose too: "Use server relay when direct fails" under Settings… in the panel (off by default). A client that has not allowed it never asks; a host that has not allowed it says so when registering, and the server refuses relay for that room's sessions (`hostnorelay`). Relay is used only when all three (server, host, client) agree.

It runs no game logic and stores nothing on disk; after a restart, rooms come back with the hosts' heartbeats.

The lobby helper **ships with no server address**: to use the lobby server, host one (or use a friend's) and have both players enter the same address under online panel → Settings… → Lobby server.

## Running

Relay has two switches: `--relay` turns both on; `--relay-watch` relays only the spectator stream, **not matches**; `--relay-match` relays only matches.

All it needs is Node.js 18+ (built-in modules only, **no `npm install`**):

```bash
node server/fornet-lobby-server.mjs                 # UDP 27020 by default, all interfaces, IPv4 + IPv6 (dual stack)
node server/fornet-lobby-server.mjs --port 27020 --host 0.0.0.0 --quiet     # IPv4 only
node server/fornet-lobby-server.mjs --host 0.0.0.0,2001:db8::5              # IPv4 + one specific IPv6 address (see below)
node server/fornet-lobby-server.mjs --relay          # turn relay on (off by default)
```

The environment variables `PORT` / `HOST` work too (relay is command-line only; `RELAY=1` is ignored).

**IPv6**: the default `--host ::` takes IPv4 and IPv6 on one port (falls back to IPv4 only if the system has no IPv6). Add an AAAA record to your domain and IPv6-only players can connect.
**If the machine has several public IPv6 addresses**, don't use the default `::`: the system picks the reply's source address itself, which may not be the one the player sent to, and the player's router / firewall drops the reply as unsolicited.
Use `--host 0.0.0.0,<the IPv6 your AAAA record points to>` instead (comma-separated, one socket per address, replies leave from the socket that received).

**Should you turn relay on?** Relay is almost all of a server's bandwidth: with direct connections the server only sees heartbeats and lists; each relayed pair is about 50 KB/s (0.4 Mbps, about 180 MB an hour). Hole punching tends to fail behind symmetric NAT / carrier-grade NAT (common on mobile networks and broadband without a public IP) and on office / school networks; without relay those players can only have the host forward a port / use UPnP, or switch to Tailscale. For a few friends with bandwidth to spare, turn it on; for a public server open to strangers, consider leaving it off so traffic costs don't run away. A stats line (rooms, sessions, packets in, relayed, dropped) is printed every minute.

## Server-hosted rooms (off by default)

The server can open a room itself, without any player hosting: roster / slots / rules / start and end / scoring / chat / spectating are all run by the server; players still exchange state directly after the server introduces them, and fall back to server relay if that fails (needs `--relay`). Supports 1v1 (commentator style, slot 1 is the match host) and multiplayer free-for-all (the server sends `mpm=`).

```bash
node server/fornet-lobby-server.mjs --room 1v1 --room-id SRV1V1 --relay
node server/fornet-lobby-server.mjs --room mp --room-size 4 --relay \
     --room-tl 180 --props "p1@0,0,0;p2@1000,0,0" --pick-range 5
```

| Option | Meaning |
|---|---|
| `--room 1v1` / `--room mp` | Open a server room; none if omitted (default) |
| `--room-id` / `--room-name` / `--room-map` | Room code / name in the list / map name |
| `--room-size` | Players in a multiplayer room (default 4, 2–16) |
| `--room-rules` | Rule string (`bar=2;bo=3;dm=150;…`); defaults if omitted |
| `--room-tl` | Match time limit (seconds) |
| `--props` / `--pick-range` | Pickup positions `id@x,y,z;…` / allowed pickup distance |
| `--cfg` | Value table (served through the same `CFGQ` as the normal lobby) |

### Server-room authentication / rate limits (on by default)

When a player joins a server room, the server sends a random **session token** (field 7 of `SHOST`, 16 characters, sent only to that player). From then on the player's state packets (`SSTATE`), relay (`SRLY` / `SRELAY`), low-rate reports / pickups (`SREPORT`), chat (`SCHAT`) and leave (`SLEAVE`) must carry the token and come from **the endpoint the player joined from**. A wrong token, a new endpoint without a new handshake, or a sender not in the room is dropped and counted (log `[room-sec]`). **Older lobby helpers have no token, so in a server room their reports / chat / relay are dropped and the room is unusable for them**; the normal lobby / ranked / spectating protocols are unchanged and older versions work as before.

If NAT changes the public port, the client handshakes again with the old token in field 6 of `JOIN`; the server treats it as the same player, updates the endpoint and keeps the slot.

Each source endpoint gets a token bucket per message type (capacity = the per-second limit, 1 second of burst). More than `--sban-drops` drops within `--sban-window` seconds bans the endpoint for `--sban-sec` seconds, then it recovers automatically. At most one log line per endpoint per minute (every 5 minutes with `--quiet`), with only room / endpoint (`--quiet`: first two parts of the IP) / reason / counts, never chat text.

| Option | Default | Meaning |
|---|---|---|
| `--srate-state` | 60 | State packets per endpoint per second (the game sends 30/s) |
| `--srate-relay` | 60 | `SRLY` relay packets per endpoint per second (30/s in game) |
| `--srate-chat` | 3 | Chat per endpoint per second |
| `--srate-pick` | 5 | Pickup reports per endpoint per second |
| `--srate-report` | 20 | `SREPORT` per endpoint per second (clients send 4/s) |
| `--srate-join` | 10 | `JOIN` per endpoint per second (clients send 1/s) |
| `--srate-srelay` | 10 | `SRELAY` requests per endpoint per second (clients send one every 5 s) |
| `--smax-packet` | 1400 | Max bytes per server-room packet, header included (a state packet is about 0.9 KB) |
| `--sban-drops` | 100 | Rate-limit drops within the window before an endpoint is banned |
| `--sban-window` | 10 | That counting window (seconds) |
| `--sban-sec` | 30 | Temporary ban length in seconds (0 = never ban) |

These options also read environment variables such as `FORNET_SRATE_STATE` / `FORNET_SBAN_DROPS` (name = option without `--`, `-` → `_`, prefixed `FORNET_`). They only apply to `--room` server rooms; the normal lobby's `RELAY_RATE` / `WATCH_RATE` are unchanged.

**Update the server and the lobby helper together**: a new lobby helper against an old server (no token in field 7 of `SHOST`) has an empty token; `SSTATE` / `SRLY` / `SRELAY` still get through the old server's parser, but chat gains an empty field and `SREPORT` / pickup fields shift; the old server also has no authentication / rate limits. Update the server first and then the players, or the other way round, but don't mix them for long.

Players enter such a room with "Join room" in the lobby helper (command line `--join-room <room code>@<server>`); no bridge platform is needed, and the release build `FornetLobby-release.exe` works too. The server only cross-checks what players report (match timer, downs / kills reported by both sides, pickup distance and order); it does not run the game or see players' screens. Spectators enter with the normal "Spectate" (server rooms can be watched without `--relay`; forwarding is low-rate, 4 per second).

## Sharing rooms with other servers (`--upstream`)

```bash
node server/fornet-lobby-server.mjs --upstream other.example.com:27020   # --upstream may be given several times
```

**Only your server (A) needs the other server's (B) address; B changes nothing.** Every 2 seconds A:

- pushes the rooms registered on it to B (B takes them like a normal host registration and drops them after 10 seconds without a push)
- fetches B's list like a client does (B's own rooms + rooms others pushed to B)

So players on A see B's rooms and players on B see A's, marked `[linked]` in the list.
To join a room on another server, the client **joins at the server the room lives on** (that server does the introductions and relay: the host's router only opened a path to its own server).
A pushes only its own rooms and skips its own rooms when they come back in B's list, so nothing loops; at most 200 rooms are accepted per source.

Note: B accepts rooms pushed by anyone (just as anyone can register a room), so fake rooms can show up in the list. Clicking one sends the client to the "server" the room claims, which then sees that player's public IP (the same exposure as joining by IP directly), and lists can be spammed. An allow-list of servers B accepts pushes from can be added later if needed.

## Ranked ban list (`--bans`)

```bash
node server/fornet-lobby-server.mjs --ranked ranked.json --bans bans.txt   # ranked ban list
# The ranked module is not part of this repository: by default it is ranked.mjs next to this file; --ranked-module <path> / RANKED_MODULE choose another
```

The environment variable `FORNET_BANS` works too.

- **Ban list** (ranked only): one ranked pid per line (a hash of the player's local key, visible in the leaderboard backend), `#` starts a comment, the file is re-read within 5 seconds of a change. Listed players get `banned` when they register or join ranked rooms. Normal rooms are not affected. Bans are by pid only: the server stores no bridge-platform identifiers.
- **There is no reporting feature**: no `--reports` / `--dump-reports`, no `REPORT` packets, no `evidence/`. Players with a problem contact the server's operator; blocking someone is local (the client's `blacklist.txt`, hashes only).
- If an old `reports.jsonl` / `evidence/` is still on your server, delete it.

## Deployment

To host one you need:

- A server with a public IP that can run Node.js 18+
- Firewall / cloud security group allowing **UDP 27020** (or your port) inbound. **UDP, not TCP**: an nginx reverse proxy does not help
- Something to keep it running, such as systemd (example below)

```ini
# /etc/systemd/system/fornet-lobby.service
[Unit]
Description=4net lobby server
After=network.target

[Service]
ExecStart=/usr/bin/node /opt/fornet-lobby/fornet-lobby-server.mjs --port 27020
Restart=always
User=nobody

[Install]
WantedBy=multi-user.target
```

Players then enter `server IP or domain:27020` under online panel → Settings… → Lobby server (the port can be left out when it is 27020).

Traffic: with direct connections the server only sees heartbeats and lists, almost nothing; with relay, each relayed pair is 30 packets/s each way of a few hundred bytes, about 50 KB/s in total.
Tested only on Node 24 (Windows); Linux and other Node versions have not been tried.

## Protocol

See the header of `fornet-lobby-server.mjs`. Text UDP packets: `4N|…` are control messages, `4NR|<session>\n<state packet>` is relayed data.

## Wire names

`4N|` / `4NR|` / `FORNET_` above are 4net's neutral names. A game whose players already use another set (say control packets `XYZS|` and peer packets `XYZHELLO`)
must run the server with the same names as its lobby helper (`Configure` in `lobby/WireTag.cs`). Two ways:

- start it with `--wire-server XYZS --wire-peer XYZ` (add `--wire-alias 4N` to also accept neutral clients; replies use whichever the sender used);
- or have the game's release script replace the whole line marked `@wire-defaults` (`WIRE_DEFAULTS`) with its own defaults (environment variable prefix, ranked module file name and server-room default map are on that line too), so nothing has to be remembered at deploy time.
